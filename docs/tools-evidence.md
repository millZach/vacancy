The parser keeps those strings and never sums image virtual sizes or calls them host reclaimed bytes. Sources: [Docker CLI verbose formatter, v28.5.1](https://github.com/docker/cli/blob/v28.5.1/cli/command/formatter/disk_usage.go), [image formatter](https://github.com/docker/cli/blob/master/cli/command/formatter/image.go).

Manifest reads use a single retained filesystem identity chain for confinement and access. Each child is opened relative to its held parent (`NtOpenFile` / `openat`); parents remain held through the read. Read bytes come only from the held ordinary file, after the current path's identity chain is revalidated. Attribute-only junction retagging is still possible despite Windows sharing restrictions, so sharing alone is never treated as the no-follow boundary. POSIX names can move immediately after the final identity check; the held descriptor continues to name the file actually authorized, rather than reopening its path. [Windows file sharing](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [FSCTL access rules](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/4aeefef8-92c3-4abc-af7a-a610caf8a165).

Unix query teardown signals the dedicated process group. This terminates group members; it does not contain a descendant that uses `setsid` or otherwise leaves that group. Output reads and deadlines remain independently bounded. No native cleanup adapter is enabled, and process groups must not be presented as an OS sandbox when mutation is designed.

Windows fixture junction creation now receives its fixture root explicitly, retains a no-follow parent chain confined to that root by identity, and atomically creates the fresh directory relative to its held parent. `NtCreateFile` uses `FILE_CREATE`, which fails if a leaf exists, and the reparse FSCTL uses only the handle returned by that creation. There is no create-then-absolute-open gap. The fixture regression proves successful ancestor redirection, requires refusal and an unchanged outside marked-fixture inventory, and checks existing-name refusal plus normal fresh creation. This does not assert anything about mklink's internals. [Microsoft creation disposition and relative RootDirectory semantics](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-zwcreatefile).
