# Vacancy

Vacancy is a desktop app for macOS and Windows that shows where your disk space goes, proposes how to get it back, runs the plan you approve, and ends with a visual report of what it did. Its proposals also cover reorganizing messy folders.

## What is expensive to get wrong

Vacancy deletes files permanently. A wrong rule or a bad path join destroys someone's data, and nothing can undo it.

- **Deletion is permanent, with one confirmation.** Only items listed on the confirm screen are touched, and the executor re-checks each path against the approved plan before acting.
- **Folder moves are journaled.** Every reorganization move is written to a journal before it happens, and the summary offers Undo.
- **Never follow symlinks or junctions while scanning or deleting.** On Windows, a junction can point a "cache" folder at a user's documents.
- **System and protected paths are off-limits.** The rules engine has a deny-list (OS folders, app bundles, the user's home root itself, cloud-sync roots) that no proposal can override, including AI proposals.
- **Claude proposes; it never executes (ADR 0008).** Live AI is the user's own Claude Code only, off until they turn it on, always launched with the locked-down flags and environment in ADR 0008. With privacy mode on (the default) it gets names, sizes, counts and dates only. With privacy mode off it may read files, but never the always-hidden places (keys and sign-ins, browser data, password managers and wallets), and it can never write, delete, run commands or go online. Its items pass the Guard and start unticked. Never read Claude Code's auth or config files, and never give it any tool beyond Read, Glob and Grep. Tests use the fake advisor; live calls happen only in an opt-in test or the installed app.
- **Both platforms, every time.** Paths, permissions (macOS Full Disk Access, Windows long paths and ACLs) and well-known cache locations differ. A change that touches one platform is tested on both.

## Product decisions

- Stack: Tauri 2. The Rust backend handles scanning, rules, the executor and the journal; the UI is React + TypeScript.
- Proposals: built-in rules find known junk offline (caches, temp, installers, dev build folders, duplicates, Docker/Xcode/package-manager leftovers). Tidy up's reorganization proposals come from built-in sorting rules too (`crates/vacancy-core/src/tidy.rs`), offline, from names, sizes and dates only. Live Claude (ADR 0008) lives in a docked Claude side panel left of the map (prototype `prototype/ai-advisor`, variant B). While Claude is off the panel is folded to a thin strip with a Claude button, so the map gets the full width; opened, it is the turn-on step, with the privacy notice and what always stays hidden. Once the user opens or folds it, that choice wins and is remembered across launches (localStorage, `vacancy.claudePanel`). Once on, it offers Review my plan (flags only, adds nothing), Let Claude pick (its changes go into the plan at once, its own items unticked, and it changes ticks only on the rules' proposals; Keep mine is offered only on the newest pick while the plan is as its answer left it, takes that pick's own items back out, and then puts the plan back only if the card is still the newest pick and the plan is still as its answer left it; an answer about a plan edited while Claude picked is set aside), Ask Claude (a follow-up chat on any plan item, or a folder it explained), Explain big folders (suggestions are added to the plan unticked) and Suggest Tidy up layouts (Windows only; an alternative to the built-in layout, picked per folder, under the same move rules). Every command that touches Claude's part of a scan (a job, a chat, Keep mine, a layout picked) names the scan its map came from, and the core refuses it once the drive has a newer scan; the map a slow reply carries is shown only if nothing newer has been. The core keeps every chat, per scan: the UI sends only a chat's id and the new question, and each chat holds the privacy mode it began in. It has a Privacy mode switch, on by default, that asks before it goes off. Changing it either way, or turning Claude off, ends every chat in the core in the same step as the new mode is kept, and the panel asks nothing until the core has answered; a question to an ended chat is refused, and goes again in a new chat. So a call with privacy mode on never holds a chat turn from privacy mode off, and it sends Claude's items made with privacy mode off by their name in the scan only, without Claude's note. Every answer says what it was based on. Claude's items are marked "Suggested by Claude" in the tray, the confirm dialog, the summary and Past runs. Turning Claude off keeps its items already in the plan. Tool/system advice that chooses its own targets stays passive and supplies no deletion or savings authority.
- Deletion: permanent, one confirmation. Moves stay undoable.
- Fast scan (Windows only; ADR 0007): "Fast scan (asks for admin)" beside Scan on the scan plate (prototype `prototype/fast-scan`, variant A). Windows asks for admin every time and nothing is remembered. Only the bundled reader, `vacancy-index-reader.exe`, runs elevated: it reads the drive's file index (the MFT) read-only and sends names, sizes and dates over a pipe; deleting stays unelevated and unchanged. Folders the account can't open are totals only, in a "Locked folders" block ("Other accounts on this PC", "Folders only Windows opens"), with no names, never proposed or deleted. A declined or closed prompt, a drive that isn't NTFS (no prompt then), a reader that won't start and an index that can't be read each run the normal scan, saying why. The reader is unsigned for now ("Unknown publisher"). macOS has no fast scan.
- Reorganization scope (Tidy up, Windows only): loose top-level files of Downloads, Desktop and Documents, sorted by kind (Images, Videos, Audio, Documents, Installers, Archives) and, for images, videos, audio and documents, by year, with a "Sort later" folder; at most 512 files per folder in one run (the first 512 as Windows lists the folder; the rest are counted and wait for a later run). Reviewed destination names are pinned: a move whose reviewed name is taken by the time it runs is left out with a reason, never renumbered. App controls follow the approved prototype `prototype/reorg-ui`, variant A: a Tidy up group in the plan tray (unticked), a drawer with before and after trees, the move count in the confirm dialog, and Undo per folder from the summary, the Moved slide and Past runs. Delete wins over sort (only while a delete target that takes the file is still in the plan). Moves free 0 B and never count as freed. Each folder's moves have their own journal in the app's data folder, and the run's report is kept in Past runs before any file moves (if it can't be, nothing moves); Undo works after a restart, and an interrupted run is never resumed. macOS shows no Tidy up, and its move/Undo entry points stay unsupported before mutation.

## Run, test, prove

Layout: a Cargo workspace with `crates/vacancy-core` (all disk logic, no Tauri) and `src-tauri` (a thin shell of Tauri commands over the core). The React UI lives in `src/`. Run `npm ci` once first.

- Run the app: `npm run tauri dev`. On Windows `npm run tauri` (`tools/tauri.mjs`) builds fast scan's reader, `vacancy-index-reader`, first: in debug beside the dev app for `dev`; for `build`, in release, bundled beside the app (`src-tauri/tauri.reader.conf.json`) with its SHA-256 pinned in the app (`VACANCY_READER_SHA256`). A release build without a pinned reader refuses fast scan and runs the normal scan.
- Run the UI alone: `npm run dev`, then open `http://localhost:1420`. Outside Tauri the UI uses the mock bridge in `src/bridge/` with fixture data. Add `?fixture=macos`, `&delay=1500` or `&fail=message` to see the Mac, loading and error states, `&scan=8000` for a slower mock scan, `&fda=granted` to change the Mac's Full Disk Access answer, `&unplug=20000` to unplug the fixture's last drive (the USB stick on Windows) 20 seconds in, `&run=6000` for a mock run of a plan that takes six seconds (the default is two seconds a step), `&dups=8000` for a background duplicate search that takes eight seconds after the scan (the default is six), and, for fast scan (Windows), `&fast=declined` to answer the admin prompt No (the normal scan runs, with its note), `&fast=failed` for a helper that doesn't start, `&fast=unreadable` for a file index that can't be read, and `&uac=3000` to keep the mock's admin prompt up three seconds (the default is 1.2; `&fast=ok`, the default, reads the index). Fast scan of the USB stick (exFAT) always gets the normal scan. The Windows fixture has Tidy up proposals (the macOS one has none), with mock runs and Undo; both fixtures have duplicate files. For the finish, `&moves=1` includes preview folder moves when the plan has no Tidy up of its own, `&unreadable=2` includes two unreadable history entries, and `&history=0` starts with no past runs. For live Claude, the mock (`src/bridge/mockClaude.ts`) never calls Claude: `&claude=off` (the default, off until turned on), `notfound`, `signedout`, `checktimeout` or `checkerror` (on, but asking Claude Code whether it's signed in timed out, or failed), `on`, `slow` (answers take 8 seconds and say they're slow after 1.5), `error` (a rate limit, in Claude's words) or `timeout` picks its state, `&privacy=off` starts with privacy mode off (the default is on), `&reads=unavailable` makes privacy mode off unable to let Claude open files (every call runs as if it were on, and the panel and each answer say why), and `&claudeMs=3000` makes its answers take three seconds (the default is 0.9; turning on takes as long, at most 1.2). It has canned answers for every job on both fixtures (Tidy up layouts on Windows only), adds Claude's items to the map and the tray, and lets a plan use Claude's layout.
- Test Rust: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace`. It includes `crates/vacancy-core/tests/rule_matcher.rs`, which runs Vacancy's Claude Code permission rules through the matcher Claude Code bundles (`tools/rule-matcher.mjs`, the `ignore` package pinned in `package.json`), so it needs Node and `npm ci`.
- Ask the real Claude Code (opt-in, never in CI): `VACANCY_LIVE_CLAUDE=1 cargo test -p vacancy-core --test claude live_claude` runs every job, privacy mode on, against a fixture profile, each call from an empty folder. Add `VACANCY_RECORD_CLAUDE=1` to save the answers in `crates/vacancy-core/tests/fixtures/claude/`, which the normal tests replay through the parser (record them with `ANTHROPIC_MODEL=haiku`). Claude Code's deny rules for the always-hidden places were proven with real probes; the evidence is in `docs/proof/t12-deny-probes/`, and for a moved Claude Code folder whose path holds glob characters (`[work]`), in `docs/proof/t12-glob-probe/` (`live_claude_glob_probe`, opt-in with `VACANCY_PROBE_GLOB_ROOT`).
- Test the UI: `npm run typecheck`, `npm run lint` and `npm test`.
- Types the UI gets from Rust are generated by ts-rs into `src/bindings/` when `cargo test` runs. Commit them. Never edit them by hand. ts-rs never deletes a binding, so after removing or renaming a Rust type, delete `src/bindings` and rerun `cargo test`. CI does exactly that.
- Build installers: `npm run tauri build`. Windows gets `target/release/bundle/msi/*.msi` and `target/release/bundle/nsis/*.exe`. The NSIS installer installs per user, with no admin. CI builds the universal macOS `.dmg`.
- Change the app icon: edit `tools/app-icon.html`, then run `node tools/render-icon.mjs`. It renders the icon in Edge and regenerates every size. Don't run `tauri icon` by hand, because the Windows `.ico` comes from a full-bleed second render.
- Prove a UI change: with `npm run dev` running, run `npm run ripple-strip -- --out shots` (the scan screen and the ripple and splash frame strips) and `npm run map-shots -- --out shots` (scanning, the map, a hover card, a zoomed category, an opened folder, the plan tray, the confirm dialog, the run mid-way and done, and the summary), both in Edge. Either drives the installed app over CDP with `--cdp`. Over CDP, `map-shots` frees the plan only with `--run`, and the app then deletes for real, so pass `--run` only to an app in fixture mode. `--fast` presses "Fast scan (asks for admin)" instead of Scan and waits through the admin prompt (answer Windows' real prompt yourself over CDP), so `npm run map-shots -- --cdp http://127.0.0.1:9333 --fast --run --out shots --name fixture-fast` approves and runs a plan made from a fast scan's map.
- Prove the duplicate finder: with `npm run dev` running, `npm run dups-shots -- --out shots` captures the progress pill, the map links, the duplicates panel, an unticked group, the confirm dialog, the run and the summary (repeat with `--url "http://localhost:1420/?fixture=macos&dups=6000&run=6000" --name mac`). Over CDP, `--run` approves and runs the plan (fixture mode only), `--only` takes every other proposal out of the plan first, `--sort` then ticks every Tidy up folder (one plan that deletes extra copies and sorts loose files), and `--untick <name>` unticks the group whose kept copy has that name.
- Prove Tidy up: with `npm run dev` running, `npm run tidy-shots -- --out shots --mac "http://localhost:1420/?fixture=macos"` captures the tray group, the drawer, the confirm dialog, the run moving and done, the Moved slide, the summary and its Undo, Past runs with Undo, a reopened run, and checks the macOS fixture shows none. Over CDP, `--run` approves and runs the plan (fixture mode only), `--hold <file>` and `--touch <file>` make a move skip, and `--phase undo` undoes every folder of the newest run from Past runs (run it after restarting the app to prove Undo from the journal).
- Prove the Claude panel: with `npm run dev` running, `npm run claude-shots` captures, into `shots/claude`, the panel off and folded, opened with the privacy notice and what always stays hidden, turning on, on, a job working, Review my plan, a row's Ask Claude, Let Claude pick's changes with what Vacancy left out, Keep mine and Use Claude's plan, Explain big folders with a ✳ folder's hover card, a folder chat with a follow-up and a typed question, Suggest Tidy up layouts with Claude's layout picked and its drawer, the privacy confirm, the note that changing it ended the conversation, and an answer with privacy mode off, and Claude's marks in the confirm dialog, the summary and Past runs; then not found, not signed in, a sign-in check that timed out or failed, slow with Cancel, cancelled, an error and a timeout in Claude's words, off again (folded) with Claude's items still in the plan, a pick set aside because the plan changed while Claude picked and one settled by a later edit, privacy mode off with reads unavailable (the panel and the answer say why), a macOS pass (no Tidy up layouts) and a 1024×700 pass. `--only win|states|mac|small` runs one part. It uses the mock's Claude only, and fails on a page error or a screen that doesn't say what it should.
- Prove fast scan: with `npm run dev` running, `npm run fast-shots -- --out shots --mac "http://localhost:1420/?fixture=macos"` captures the plate with both buttons, the wait while Windows asks for admin, the fast scan reading the file index and sorting it, the map with its Locked folders block (a locked tile's hover card, the block opened, the toolbar's notes), the normal scan's note in the HUD and on the map when admin is declined, the drive isn't NTFS (the USB stick), the helper doesn't start and the index can't be read, and checks the macOS plate has no fast scan. It fails on a page error or a screen that doesn't say what it should.
- Prove the finish: `npm run wrapped-shots -- --out shots --url "http://localhost:1420/?fixture=windows&run=1500&moves=1&unreadable=2" --name win`, then repeat with `fixture=macos` and `--name mac`. It captures each slide, the number-flight strip, the summary, replay, history reopen and reduced motion, and writes frame timings. The moved slide is hidden without moves. For installed fixture proof, use `--cdp http://127.0.0.1:9333 --run`; it approves and executes the plan, so the app must be in fixture mode. Without `--run`, CDP captures the completed run on screen or the newest history entry. See `tools/wrapped-shots.mjs` for capture groups and viewport options.
- Measure fast scan without admin: `cargo run --release -p vacancy-core --example fast_image -- <NTFS image>` times the reader and the snapshot on an image file and prints peak memory. The parser's test image (`crates/vacancy-index/tests/fixtures/small.ntfs.gz`, written by ntfs-3g) is regenerated in WSL by `make-image.sh` there, which says how its tools were built without root. On a real drive, `examples/fast_compare.rs` runs a fast and a normal scan and compares them folder by folder; it needs the release reader beside it and its hash in `VACANCY_READER_SHA256` at build time, and Windows asks for admin.
- Measure the scanner on a real drive (read-only): `cargo run --release -p vacancy-core --example scan -- C:\` prints time, counts, peak memory and the categories. `cargo run -p vacancy-core --example drives` lists the drives the picker offers, and how long listing took.
- Prove an app change: install the built installer, run it in fixture mode against a fixture profile, approve a plan, and check the summary against what changed on disk. **Never run a plan against a real drive or a real home folder.**
  - Make a profile: `cargo run -p vacancy-core --example fixture -- D:\tmp\vacancy-fixture-1`. It needs an empty folder outside your home, and fills it with caches, temp files, an idle pnpm-style project, a link from a cache to the profile's `Documents`, a read-only file, a path longer than 260 characters, messy loose files in Downloads, Desktop and Documents for Tidy up (a name collision, an old installer a cleanup deletes too, a file to hold open and one to change after the scan), and known duplicate files (groups for the keeper rule, some of them loose in Downloads and Desktop, plus look-alikes that must never be proposed; see `DuplicateCases` and ADR 0006). The list it prints names the file to hold open and the file to change after the scan.
  - Run the app in fixture mode by setting `VACANCY_FIXTURE_ROOT` to the folder. On Windows: `$env:VACANCY_FIXTURE_ROOT='D:\tmp\vacancy-fixture-1'; & "$env:LOCALAPPDATA\Vacancy\vacancy.exe"`. On macOS, run `Vacancy.app/Contents/MacOS/vacancy` with it set; `open` doesn't pass it on.
  - In fixture mode the drive list holds one pseudo-drive, the folder. Home, app data and temp are inside it, and the run history goes to its app data. The Guard denies everything outside the folder, by identity. A fast scan reads the index of the volume the folder is on and keeps only the folder's part.
  - The app refuses the mode, and scans and deletes nothing, if the folder is missing, is reached through a link, is a drive's root, or is in or holds your home. It never falls back to the real drives.
  - List the tree before and after with `cargo run -p vacancy-core --example fixture -- --list D:\tmp\vacancy-fixture-1 before.tsv`. The listing gives path, size and hash, never follows links, and diffs cleanly. ADR 0005 has the details.

## CI

`.github/workflows/ci.yml` runs on every PR and every push to main. It runs every check above on `windows-latest` and `macos-latest`, fails if `src/bindings` is stale, builds the installers and uploads them as artifacts.

The merge bar is two green jobs: **Test and build on Windows** and **Test and build on macOS**.

`.github/workflows/release.yml` runs on `v*` tags. It builds the installers and attaches them to a draft GitHub Release. The version is set in one place, `[workspace.package]` in `Cargo.toml`, and the tag must be `v` plus that version. The README's "Releasing" section has the steps. Never publish a release or push a version tag unless Zach asks.
